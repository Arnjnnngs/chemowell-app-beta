MUTANT 7, THE ONE THAT MATTERED

Its description claimed it was "the app-v92 defect itself ... 3 overflowing, '10:00 AM' by 5px".
The audit had already measured five variants of it and found every one clean. This sweep makes six.
`overflow-scan` cannot tell "the suite cannot see it" from "there is nothing to see", so the cell
was measured directly -- `falsify/probe-timecell-width.mjs`, used width against text width by
Range, four widths, 24 cells, shipped against the mutant:

  shipped   flex-shrink=0   used 58.03 / 66.31   text 58.03 / 66.31   squeezed below text: 0
  mutant 7  flex-shrink=1   used 58.03 / 66.31   text 58.03 / 66.31   squeezed below text: 0

Identical, with `flex-shrink` reading 1 in the mutant, so the mutation applied and did nothing. The
property is inert on every row this fixture can draw, because app-v92's own name fix removed its
precondition: the name span has `minWidth: '0'` and `overflowWrap: break-word`, so a crowded row
wraps the name instead of squeezing the time -- `Hydroxychloroquine` breaks mid-word. It stays in
the app for a future row that cannot wrap, and the mutant is relabelled `survive` with the numbers
in it. Mutants 5 and 8 are what actually pin that row. Both bite.

The alternative was to "strengthen" an instrument until a mutant died. That is how a check that
cannot fail gets built, and this file is the record of not doing it.
